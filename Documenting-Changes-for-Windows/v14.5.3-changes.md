# Windows port brief — Organize reliability + plan model split (Mac v14.5.3)

Context: a Pro-trial user (entitled, NOT a billing problem) reported: *"generate plan →
it indexes → 'new files detected' → index again → 'Could not generate organization plan.
Make sure your AI provider is configured in Settings.'"* We traced it, fixed it on Mac,
and verified end-to-end on the live model. Windows shares the same Python/Qt core, so the
**client** changes below port almost 1:1. **Use the Windows version scheme (12.x), not 14.5.3.**

The backend (Supabase `openai-proxy`) is **shared** and already updated — Windows does NOT
redeploy it. Only the client code changes are needed on Windows.

---

## TL;DR of the fixes
1. Organize **plan** was flaky because the ≤250-file path had **no retry** on gpt-5-nano (~17% of single calls failed → the error). Added retries + partial-plan + a deterministic fallback so an entitled user **never** sees that error.
2. The **plan now runs on gpt-5-mini** (cleaner plans: ~100% file coverage vs nano's ~86%). High-volume **tagging/vision stays on gpt-5-nano** (cheap, measured 0 failures). Split is enforced per-call.
3. The **"new files detected" loop** was the indexer's hardcoded 1,000-file scan cap vs the uncapped "unindexed" check. Fixed the loop + raised the cap to the user's tier.
4. A **lapsed** user now gets the resubscribe wall instead of the misleading "configure your AI provider" message.

---

## 1) `app/core/ai_organizer.py` — plan robustness + model + fallback

- Bump `_PLAN_CHUNK_RETRIES = 2` → **3**.
- Add constant `PLAN_MODEL = "gpt-5-mini"` (plans use the sturdier model; tagging stays nano).
- Add `_normalize_plan_shape(plan)`: accept a wrapper-less `{name:[ids], ...}` reply by wrapping it as `{"folders": {...}}`; return **None** for empty/garbled (so the retry kicks in). An empty `folders` dict counts as None.
- Add `_plan_with_retries(user_instruction, chunk, idx=0, n_chunks=1)`: loops up to `_PLAN_CHUNK_RETRIES`, returns a result only if `part and part.get("folders")`, else None after all attempts. **Use it for BOTH paths.**
- In `request_organization_plan`:
  - `if len(files) <= _PLAN_CHUNK_SIZE: return _plan_with_retries(user_instruction, files, 0, 1)`  ← this path previously had **NO retry** (the main bug).
  - Multi-chunk: submit `_plan_with_retries` per chunk. Then **do not abort the whole plan if one chunk fails** — keep the good ones: `good = [p for p in parts if p and p.get("folders")]`; `if not good: return None`; merge `good`; the caller's `ensure_all_files_included` conserves any dropped files.
- In `_request_plan_single`, wrap the provider result: `plan = _request_openai(...)` (or ollama) then `return _normalize_plan_shape(plan)`.
- In `_request_openai`, pass the model: `_call_openai_proxy("chat", messages, max_tokens=4000, temperature=0.1, model=PLAN_MODEL)`.
- Add `_fallback_plan_by_category(files)`: deterministic grouping by each file's `category` (or file extension if no category); returns `{"folders": {...}}` or None if no files. Never calls the network. **UI-only** — see §3.

## 2) `app/core/vision.py` — forward an allow-listed model

- `_call_openai_proxy(endpoint, messages, max_tokens=500, temperature=0.2, model=None)`: add the `model` param and include it in the POST payload **only if provided**:
  `if model: payload["model"] = model`.
- Leave ALL tagging callers (`_gpt_text_analysis`, `gpt_vision_fallback`, etc.) unchanged — they send no model → the proxy defaults them to nano. (resolve_folder_with_ai also stays nano.)

## 3) `app/ui/organize_page.py` — stop the loop + correct the error surface

- **Loop fix:** in `generate_plan`, read a one-shot instance flag and skip the unindexed re-scan after an index pass:
  ```python
  skip_index_check = getattr(self, "_skip_index_check_once", False)
  self._skip_index_check_once = False
  unindexed_files = [] if skip_index_check else self._check_for_unindexed_files()
  ```
  Set `self._skip_index_check_once = True` right before the `QTimer.singleShot(..., self.generate_plan)` re-invocations in `_on_index_before_organize_finished` (both branches) and `_on_index_skip_requested`. (Use an instance flag, NOT a method arg — the button's `clicked` signal would pass a `checked` bool.)
- **Error surface:** in `_on_plan_received`, replace the `if not plan:` block. First check entitlement; route a lapsed user to the wall, otherwise fall back (never the misleading settings message):
  ```python
  if not plan:
      try:
          from app.core.supabase_client import supabase_auth
          entitled = bool(supabase_auth.get_entitlement().get('entitled', True))
      except Exception:
          entitled = True
      if not entitled:
          self.status_label.setText("Subscription inactive.")
          mw = self.window()
          if mw and hasattr(mw, '_show_resubscribe_wall') and not getattr(mw, '_entitlement_wall_open', False):
              mw._show_resubscribe_wall()
          return
      from app.core.ai_organizer import _fallback_plan_by_category
      plan = _fallback_plan_by_category(list(self.files_by_id.values()))
      if not plan:
          QMessageBox.warning(self, "Plan Failed", "Could not generate an organization plan. Please try again in a moment.")
          return
      self.status_label.setText("AI was busy — grouped files by type. Review and refine before applying.")
  # ...then fall through to the existing deduplicate_plan / ensure_all_files_included / render
  ```
- **Voice path:** in `_voice_on_plan`, mirror it — on `not plan`, if not entitled emit "Your subscription is inactive — please resubscribe to keep organizing."; else use `_fallback_plan_by_category(list(self.files_by_id.values()))`; if still nothing, keep the old "couldn't make a plan" message.
  (Windows voice-organize uses the same `PlanWorker`/`request_organization_plan`, so the mini switch is automatic there.)

## 4) `app/core/search.py` — index cap scales to tier (root of the loop)

- In `index_directory`, before scanning, cap by the user's tier instead of a hardcoded 1,000:
  ```python
  try:
      from app.core.supabase_client import supabase_auth
      scan_cap = supabase_auth.get_index_limit() if supabase_auth.is_authenticated else 1000
  except Exception:
      scan_cap = 1000
  if not scan_cap or scan_cap <= 0:
      scan_cap = 1000
  files = scan_directory(directory_path, max_files=scan_cap)
  ```
- `INDEX_LIMITS = {'basic':1000, 'pro':5000, 'premium':50000}`; `get_index_limit()` already exists. **Do not touch** `_check_index_limit` (the paid media-quota gate stays all-or-nothing as before). Note `scan_directory`'s `max_files` caps TOTAL files; the quota is media-only — acceptable, still far better than 1,000.

## 5) Backend — `openai-proxy` (SHARED, already deployed; for your understanding only)
- Added `const CHAT_MODEL_ALLOWLIST = new Set(["gpt-5-nano","gpt-5-mini"]);` and chat/vision now does `const model = CHAT_MODEL_ALLOWLIST.has(requested) ? requested : ALLOWED_CHAT_MODEL;` (default nano). Old/other clients that send no model keep getting nano unchanged.
- Added `"gpt-5-mini": { input: 25, output: 200 }` to `COSTS_PER_MILLION` (cents/1M).
- ⚠️ **verify_jwt must stay `false`** — the function does its own `supabase.auth.getUser` + 401-refresh. The deploy tool defaults verify_jwt to true; if it flips, the token-refresh flow breaks. (We had to redeploy to set it back.)

## 6) Version
- Bump Windows version per its own scheme (12.x) + the CFBundle/installer version strings. Don't copy 14.5.3.

## What "fixed" looks like (verification targets)
- **A/B nano vs mini** (identical inputs): nano 86–89% file coverage, 1.4× id-bloat; **mini 99–100%, ~1.0×**; both 0 user-facing failures after the retry fix.
- **100-call scale test:** 70 mini plans → **0 failures, 100% coverage**; 30 nano tagging → 0 failures; model split exact (70 mini / 30 nano).
- **End-to-end** (real files): Organize Now, auto-organize (watcher), and voice all indexed, planned, and **moved real files**; every plan ran on mini, every tag on nano.

## Gotchas / rationale
- All three planning paths share `request_organization_plan` (manual Organize, no-instruction auto mode, and the background auto-watcher), so the retries + partial-plan + mini apply to all of them automatically.
- The deterministic by-type **fallback is UI-only**. The background auto-watcher deliberately does NOT use it — it moves files without a human preview, so on a rare failure it should skip + retry next scan rather than auto-apply a degraded plan.
- nano is bad only at the PLAN (big structured JSON + "cover every id" constraint); it's fine at tagging (tiny output, no hard constraint, and a miss just indexes a file with lean tags — never an error). That's why only the plan moved to mini.
- Cost: mini ≈ 5× nano per plan, but plans are rare → pennies/user/month; tagging (the volume) stays nano.
