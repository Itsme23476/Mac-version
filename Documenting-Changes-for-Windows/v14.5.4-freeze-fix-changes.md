# Windows port brief — Organize "Not Responding" freeze fix (Mac v14.5.4)

Context: a Windows user (Pro plan) reported the app shows **"(Not Responding)"** when they
organize a folder. Root cause is in the **shared** Python/Qt core, so Windows has it too.
Port the change below. Use the Windows version scheme (12.x), **not** 14.5.4.

## Root cause
The organize "Generate Plan" entry (`OrganizePage.generate_plan` in `app/ui/organize_page.py`)
did its heavy work **on the main/UI thread** before handing off to the AI worker:
- `_check_for_unindexed_files()` → a full recursive `os.walk` of the folder
- `_verify_and_fix_paths()` → **another** full `os.walk` + per-file `os.path.exists`
- `_load_files_from_db()` → load every row + build dicts

On a big / slow / cloud (OneDrive) folder that blocks the event loop → Windows paints
**"Not Responding"** (macOS shows the beachball). The AI call itself was already on a worker;
it's this pre-plan scanning that freezes the UI.

## The fix (one file: `app/ui/organize_page.py`)
Move those heavy scans onto a background `QThread`; keep every dialog/decision on the main
thread, driven by the worker's signal. **Do not change the logic of the three heavy helpers**
— only *where they run* — except making `_verify_and_fix_paths` GUI-free (below).

### 1) New worker class
Add near the other QThread workers (e.g. after `IndexBeforeOrganizeWorker`):
```python
class OrganizePrepWorker(QThread):
    """Runs the heavy, blocking parts of organize prep OFF the UI thread so the app never
    freezes. Only calls the page's existing (now GUI-free) helpers; dialogs stay on the
    main thread in the slot that receives `done`.
        mode 'check_unindexed' -> {'mode','unindexed': [...]}
        mode 'load_verify'     -> {'mode','stage':'nofiles'}
                               or {'mode','stage':'ready','files':[...],'original_count':N}
        on failure             -> {'mode', 'error': '...'}
    """
    done = Signal(dict)
    def __init__(self, page, mode: str):
        super().__init__(); self.page = page; self.mode = mode
    def run(self):
        try:
            if self.mode == "check_unindexed":
                self.done.emit({"mode": "check_unindexed",
                                "unindexed": self.page._check_for_unindexed_files()})
            else:  # load_verify
                files = self.page._load_files_from_db()
                if not files:
                    self.done.emit({"mode": "load_verify", "stage": "nofiles"}); return
                original_count = len(files)
                files = self.page._verify_and_fix_paths(files)
                self.done.emit({"mode": "load_verify", "stage": "ready",
                                "files": files, "original_count": original_count})
        except Exception as e:
            logger.error(f"OrganizePrepWorker ({self.mode}) failed: {e}")
            self.done.emit({"mode": self.mode, "error": str(e)})
```

### 2) `generate_plan` becomes an async state machine
Split the old `generate_plan` body into FOUR methods. **Keep every dialog, its exact text,
the order, and the index-then-retry loop identical** — you're just relocating the blocks:

- `generate_plan(self)`:
  - read `instruction`; return if no destination.
  - **Re-entry guard** (new — the old sync version was implicitly guarded by the freeze):
    `if getattr(self,"_prep_worker",None) is not None and self._prep_worker.isRunning(): return`
  - `skip_index_check = getattr(self,"_skip_index_check_once",False); self._skip_index_check_once=False`
  - `self._pending_instruction = instruction`
  - if `skip_index_check`: `self._continue_after_unindexed(); return`
  - else: disable the Generate button, set status "Scanning folder…", start
    `OrganizePrepWorker(self,"check_unindexed")` connected to `self._on_prep_done`, `.start()`.

- `_on_prep_done(self, result)`:
  - if `result.get("error")`: re-enable button, status "Couldn't scan the folder.", return.
  - if `result["mode"]=="check_unindexed"`: if `result["unindexed"]` → show the **"New Files
    Detected"** dialog (your existing one). Index Now → `self._index_folder_before_organize(...)`;
    Skip → fall through. Then `self._continue_after_unindexed()`.
  - else (`load_verify`) → `self._on_files_prepared(result)`.

- `_continue_after_unindexed(self)`:
  - `instruction = getattr(self,"_pending_instruction","")`
  - the existing **excluded-file-types** check (re-enable + return on hit).
  - the existing **Auto-Organize Mode** dialog when `instruction` is empty (re-enable + return on
    Cancel; else set the `[AUTO-ORGANIZE] …` instruction).
  - `self.original_instruction = instruction; self._pending_instruction = instruction`
  - disable button, status "Loading your files…", start `OrganizePrepWorker(self,"load_verify")`
    connected to `_on_prep_done`, `.start()`.

- `_on_files_prepared(self, result)`:
  - if `result.get("stage")=="nofiles"`: the existing **"Index Files First?"** / **"No Files"**
    logic (re-enable button on the exits that previously just `return`).
  - else: `files = result["files"]; original_count = result["original_count"]` then the existing
    post-verify **exclusion re-filter**, `self.files_by_id = {…}`, the **"No Valid Files"** check,
    the **subfolder-context** loop, and finally spawn `PlanWorker(self.original_instruction, files)`
    exactly as before.

### 3) Make `_verify_and_fix_paths` GUI-free
It runs on the worker now, so it must NOT touch any Qt widget. Delete its
`self.status_label.setText(...)` block (and the dead `msg_parts` lines) — keep the `logger.info`
and the DB `update_file_path` logic. Nothing else in that method changes.

### Button enable/disable
The old code disabled the Generate button only at the very end; now you disable it when a prep
worker starts, so **re-enable it on every early-return path** (prep error, excluded types,
auto-organize cancel, no-files, no-valid-files). `_on_plan_received`/`_on_plan_error` already
re-enable it for the AI step.

## Do NOT change
- The three helpers `_check_for_unindexed_files`, `_load_files_from_db`, `_verify_and_fix_paths`
  (except the `_verify` GUI-call removal). They're thread-safe (own sqlite connections, os.walk).
- The voice path — it already avoids `_verify_and_fix_paths` (its os.walk was known-heavy).
- The auto-watcher — already runs on its own thread.

## Gotchas
- Use an **instance flag** (`_skip_index_check_once`, `_pending_instruction`), NOT a method arg —
  the button's `clicked` signal passes a `checked` bool that would land in a positional param.
- `IndexProgressDialog` is shown with `.show()` (non-modal) — fine.
- `Dict`/`Any` are already imported in the file (used in type hints).

## How to verify (what I did on Mac)
- **Freeze proof (the key one):** inject a deliberately slow scan and confirm `generate_plan()`
  returns instantly. On Mac: monkeypatched `_check_for_unindexed_files` to `sleep(1.5)` then
  called `generate_plan()` — it returned in **0.000s** (on the old code it blocked the full 1.5s).
- Headless: drove the real `OrganizePage.generate_plan` with the actual workers + auto-answered
  dialogs → plan produced, covered all files, no exceptions.
- Unit-tested the worker's 4 branches (check_unindexed / none / nofiles / ready / error).
- `py_compile` + import under Qt, then a live run on a 60-file folder: indexed, planned, moved,
  no freeze/errors.

Net effect: organize stays responsive on big/slow/cloud folders; identical dialogs and flow.
