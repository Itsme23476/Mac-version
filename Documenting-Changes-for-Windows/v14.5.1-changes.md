## 1. SSL / certifi streaming fix  ⚠️ CRITICAL — same bug on Windows

**Problem.** In a frozen build (PyInstaller/py2exe), Python's **stdlib `ssl` has no default
CA bundle**. So any `wss://` connection via the `websockets` lib (used for the
`transcribe-stream` edge function) fails the TLS handshake with
`CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate`, and the streaming
transcriber **silently falls back to the slow batch path** (`transcribe` endpoint).
`requests`/`httpx` are unaffected because they carry their own `certifi` — which is why the
batch path works and streaming doesn't, *only in the frozen app* (dev works fine because
stdlib ssl finds the system certs).

**Symptom.** Voice dictation feels much slower in the shipped app than in dev. Logs show
`[STREAM] connect failed (...CERTIFICATE_VERIFY_FAILED...); batch fallback` on every dictation.

**Fix.** Build an `SSLContext` from `certifi` and pass it to `websockets.connect(..., ssl=ctx)`.
In the Mac code this is in `app/core/transcription.py`, `StreamingTranscriber._session()`,
right before the connect:

```python
# wss:// uses stdlib ssl, which in a frozen bundle has NO default CA bundle — without an
# explicit one the TLS handshake fails and streaming silently falls back to batch.
ssl_ctx = None
try:
    import ssl as _ssl, certifi
    ssl_ctx = _ssl.create_default_context(cafile=certifi.where())
except Exception as e:
    logger.warning(f"[STREAM] certifi ssl context unavailable ({e}); using default")

if token and websockets is not None:
    connect_kwargs = {
        "additional_headers": {"Authorization": f"Bearer {token}"},
        "max_size": None,
    }
    if ssl_ctx is not None:
        connect_kwargs["ssl"] = ssl_ctx
    ws = await asyncio.wait_for(
        websockets.connect(self._build_url(), **connect_kwargs), timeout=8)
```

**Windows action:**
- Find the streaming transcriber's `websockets.connect(...)` call and add `ssl=<certifi ctx>`
  the same way.
- Ensure `certifi` is bundled in the Windows frozen build (data file + hidden import). It
  almost certainly already is, because `requests` depends on it.
- Note: `websockets.connect` in v14+ forwards unknown kwargs (incl. `ssl`) via `**kwargs`
  to the asyncio connection, so `ssl=` works even though it's not an explicit param.

**How to verify on Windows:** dictate in the *frozen* build and check the log for
`[STREAM] connected in 0.4s` (fixed) vs `connect failed ... CERTIFICATE_VERIFY_FAILED`
(still broken).

## 2. Spoken-number formatter (`dictation_format.py`)  — copy verbatim

**Why.** The STT model (Grok Voice Transcribe 2.0) returns everything **spelled out**
("ten thousand dollars", "fifty percent"). This module converts the high-confidence,
context-free cases to written form, instantly and for free (pure Python, no API call):
`"ten thousand dollars"` → `"$10,000"`, `"fifty percent"` → `"50%"`,
`"twenty five dollars and ninety nine cents"` → `"$25.99"`.

**Safety:** it only converts *multi-word* number spans (real quantities) + currency/percent
contexts; a lone small number in prose ("I have **one** question") and all other text are
left untouched. Lossless on anything it doesn't recognize.

**Windows action:** copy the module **verbatim** (it's plain Python, no Mac-isms) to the
equivalent `app/core/dictation_format.py`, then call it in the dictation finalize path —
on Mac that's `app/ui/dictation.py`, `_on_final()`, right after the text is stripped and
before it's pasted/saved:

```python
try:
    from app.core.dictation_format import format_spoken
    text = format_spoken(text)
except Exception as e:
    logger.warning(f"number formatting skipped: {e}")
```

Add `app.core.dictation_format` to the Windows build's hidden imports.

The full module (copy this):

```python
"""Deterministic spoken-number -> written-form formatter for dictation output."""
import re

_ONES = {"zero":0,"one":1,"two":2,"three":3,"four":4,"five":5,"six":6,"seven":7,"eight":8,
    "nine":9,"ten":10,"eleven":11,"twelve":12,"thirteen":13,"fourteen":14,"fifteen":15,
    "sixteen":16,"seventeen":17,"eighteen":18,"nineteen":19}
_TENS = {"twenty":20,"thirty":30,"forty":40,"fifty":50,"sixty":60,"seventy":70,"eighty":80,"ninety":90}
_SCALES = {"hundred":100,"thousand":1000,"million":1000000,"billion":1000000000}
_NUMWORD = set(_ONES) | set(_TENS) | set(_SCALES)
_W = r"(?:%s)" % "|".join(sorted(_NUMWORD, key=len, reverse=True))
_SEQ = r"%s(?:[\s-]+(?:and[\s-]+)?%s)*" % (_W, _W)

def _parse_cardinal(phrase):
    total = current = 0
    for w in re.split(r"[\s-]+", phrase.lower()):
        if w in ("", "and"): continue
        if w in _ONES: current += _ONES[w]
        elif w in _TENS: current += _TENS[w]
        elif w == "hundred": current = (current or 1) * 100
        elif w in _SCALES: total += (current or 1) * _SCALES[w]; current = 0
    return total + current

def _is_multiword(phrase):
    return bool(re.search(r"[\s-]", phrase.strip()))

def format_spoken(text):
    if not text or not text.strip(): return text
    try:
        s = text
        s = re.sub(r"\b(%s)\s+dollars\s+and\s+(%s)\s+cents\b" % (_SEQ, _SEQ),
            lambda m: "$%s.%02d" % (f"{_parse_cardinal(m.group(1)):,}", _parse_cardinal(m.group(2))),
            s, flags=re.IGNORECASE)
        s = re.sub(r"\b(%s)\s+dollars\b" % _SEQ,
            lambda m: "$%s" % f"{_parse_cardinal(m.group(1)):,}", s, flags=re.IGNORECASE)
        s = re.sub(r"\b(%s)\s+percent\b" % _SEQ,
            lambda m: "%s%%" % f"{_parse_cardinal(m.group(1)):,}", s, flags=re.IGNORECASE)
        s = re.sub(r"\b(%s)\b" % _SEQ,
            lambda m: f"{_parse_cardinal(m.group(1)):,}" if _is_multiword(m.group(1)) else m.group(0),
            s, flags=re.IGNORECASE)
        return s
    except Exception:
        return text
```

⚠️ **IMPORTANT — the snippet above is out of date.** In **v14.5.2** the formatter was
hardened (deep testing found a data-corruption bug): it now (a) only converts *well-formed*
cardinals, so a spoken **digit sequence** like "five five five one two three four" or a year
"nineteen eighty four" is **left as words** instead of being summed into a wrong number
("25" / "103"); (b) handles **decimals** ("three point five" → "3.5"); and (c) also fixes
**digit-form** `$`/`%` left by the LLM cleanup ("10,000 dollars" → "$10,000"). **Copy the
CURRENT `ai_file_organizer/app/core/dictation_format.py` verbatim** (it has these fixes +
the full docstring/self-test) rather than the condensed snippet above.

## 3. "AI Cleanup (optional)" onboarding step

**Why.** AI Cleanup (the LLM polish/formatting pass) is **off by default** (opt-in). To make
it discoverable, we added an onboarding step that navigates to the **Voice tab** and
spotlights the AI Cleanup toggle, so users learn it exists and can flip it on.

**Copy used:**
> **✨ AI Cleanup (optional)**
> • Off by default — your dictation stays instant
> • Turn it on to auto-format dates & emails and strip filler
> • Adds ~1s per dictation — flip it on here anytime

**Mac implementation** (`app/ui/onboarding.py`): inserted a step dict into `self.steps`
right after the "🎤 Talk to Filect" step (nav_index = the Voice page, `highlight` = the
cleanup card). **Gotcha:** the per-step animation is keyed by step index
(`if self._step == N`), so inserting a step shifted the later animations — had to remap
those branches and update the `_STEP_SLUGS` list to keep everything aligned. **Windows:
check whether its onboarding has the same index-keyed structure and remap accordingly.**

## 4. Eligibility-aware, price-free paywall

**Why.** With the $15/$25 A/B test on the web, the in-app paywall must **not** quote a fixed
price (it would mismatch whatever the web shows). The old page hardcoded "from $15 / mo".

**New behavior** (Mac `app/ui/auth_dialog.py`, `_show_subscribe_page()`): the copy is chosen
by trial eligibility, determined from the cached subscription record
(`supabase_auth._subscription is None` ⇒ never subscribed ⇒ trial-eligible). No network call.

| State | Badge | Headline | Button |
|---|---|---|---|
| Never subscribed (trial-eligible) | `10-DAY FREE TRIAL` | `Free` / `for 10 days` | `Start free trial` |
| Lapsed (had a subscription) | `CHOOSE YOUR PLAN` | `Full` / `access` | `View plans` |
| Card already used (post-checkout lock) | `CHOOSE YOUR PLAN` | `Full` / `access` | `Subscribe to unlock` |

**No `$` price in any state.** The button still opens the web pricing page (where the real
bucketed price + checkout live) — *button functionality unchanged*. Subtitle: "All features ·
cancel anytime" (eligible) / "Choose a plan to continue · cancel anytime" (lapsed).

**Windows action:** replicate in its auth-dialog/paywall — remove any hardcoded price, lead
with the free trial for trial-eligible users (`_subscription is None`), neutral "choose a
plan" otherwise. (On Mac, lapsed users mostly hit a *separate* `ResubscribeWall`, which was
already price-free — verify the Windows equivalent is too.)

Also verify Windows has the price→tier fallback so the new $25 price just works:
`PRICE_TO_TIER.get(price_id, 'basic')` → unknown price → Basic tier (1,000 media limit).

## 5. Server-side / model changes (SHARED — no Windows code change)

All of these are in the **same Supabase project** both apps use, and are **already deployed**.
Windows benefits automatically; listed here for awareness only.

- **`openai-proxy`** now forces **gpt-5-nano** for ALL chat + vision calls (it ignores the
  model the client sends). So **image indexing, organize plans, and search rerank all use
  nano** already — on Mac *and* Windows. nano is cheaper ($0.05/$0.40 per 1M in/out vs
  gpt-4o-mini's $0.15/$0.60) and, for images, avoids gpt-4o-mini's ~25k-token-per-image
  penalty. (This edge function was deployed inline; it is **not** in the repo.)
- **`clean-transcript`** (dictation AI Cleanup): switched to **gpt-5-nano** + a prompt that
  now also does Whispr-style context formatting — dates, times, emails, phone numbers, math
  symbols, %, currency — on top of grammar cleanup. (In repo:
  `supabase/functions/clean-transcript/index.ts`.) GPT-5 is a reasoning model, so the request
  uses `max_completion_tokens` + `reasoning_effort:"minimal"` and **no** `temperature`.
- **`distill-query`** (voice search): **left on gpt-4o-mini** on purpose — voice search is
  latency-critical and nano's reasoning adds ~1s; the cost is negligible.
- **`get_entitlement` RPC**: removed the 14-day `past_due` dunning grace. A failed payment
  now loses access **immediately** (no grace); only `active`/`trialing` (not expired) grant
  access. Server-side → **Windows already gets this, no code change** — the resubscribe wall
  just triggers sooner. (The client-side *offline* grace, which protects a paying user who
  is temporarily offline, is unchanged.)

**Division of labor:** the always-on deterministic formatter (#2) handles numbers/$/% with
zero latency for *everyone*; the opt-in AI Cleanup (#3, server-side nano) adds the
context-heavy stuff (emails/dates/symbols) + grammar, at ~1s, only when the user turns it on.
