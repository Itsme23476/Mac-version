# v14.6.0 — Voice batch (for the Windows port)

Mac branch: `voice-streaming`. All changes are dictation/transcription quality + a custom-words
suggester. No backend changes (the `transcribe` edge function already accepts `X-Audio-Terms`).

## 1. Deterministic formatting (runs with AI Polishing OFF) — PORT AS-IS
`app/core/dictation_format.py` is pure Python, platform-independent. Port verbatim.
- `format_spoken(text)` — spoken numbers/currency/percent → written form ("twenty five dollars" → "$25").
- `tidy_text(text)` — collapse double spaces, fix space-before-punctuation, pronoun "i" → "I",
  capitalize after sentence-ending punctuation.
- `apply_sentence_case(text, before_caret, custom_terms)` — capitalize at start of field / after
  `. ! ?` / newline; drop a stray leading capital mid-sentence; **protect acronyms + Custom Words**.
  If `before_caret` is `None`, it leaves text unchanged (safe no-op).

These run in `dictation.py::_on_final` for BOTH raw and polished output, so formatting is identical
whether or not Polishing is on. Self-checks: `python app/core/dictation_format.py`.

## 2. Context-aware capitalization — NEEDS A WINDOWS EQUIVALENT
`apply_sentence_case` needs the character immediately before the caret to know if the new text
starts a sentence. On Mac this comes from `app/ui/mac_hotkey.py::text_before_caret()` via the
**Accessibility API** (AXUIElement → focused element → selected range → value; skips secure fields).

**Windows:** implement a `text_before_caret()` that returns ~40 chars before the caret (or `None`)
via **UI Automation** (`TextPattern`/`GetSelection`) or the Win32 caret APIs. If you can't get it,
**return `None`** — capitalization then safely no-ops and nothing breaks. This is the only
platform-specific piece in the batch.

## 3. Custom Words key-term biasing — ALREADY WORKS, VERIFY HEADER
Biasing is automatic and independent of Polishing: `settings.dictation_custom_terms` →
`transcribe_audio(..., terms=...)` → `X-Audio-Terms` header → Grok `keyterm`. The Windows client
must send the same header (and pass `terms` into its streaming path). Tested v14.6.0: biasing never
hurts (6/6 correct both on/off on identical audio) and fixes genuinely mis-heard words on real voice.

## 4. AI custom-words suggester (niche → terms) — PORT (Qt, platform-independent)
- `app/core/vocab.py` — `suggest_terms_for_niche(niche)` asks gpt-5-mini (via the existing proxy)
  for DISTINCTIVE, correctly-spelled terms for the user's field; `clean_suggestions()` +
  `_is_distinctive()` drop plain dictionary words so biasing stays useful. Self-checks:
  `PYTHONPATH=app python app/core/vocab.py`.
- `app/ui/voice_cards/vocab_suggest.py` — `VocabSuggestPanel` (niche field → Suggest → selectable
  chips, double-click to edit → "Add selected"). `show_manual_add` toggles an own-word field
  (True in onboarding, False in the Settings card which has its own Add field).
- Wired into the Settings Custom Words card and the onboarding "Teach Filect your words" step.
- `settings.add_custom_terms()` (dedup, cap 100) and `settings.dictation_last_niche` (remembers +
  prefills the last field) added. A one-line "why these words?" note sits under the chips.

## 5. DROPPED — do NOT rebuild on Windows: "learn from your dictation history"
We prototyped mining the user's dictation history to auto-suggest their own vocabulary. It is
**net-negative for a biasing list** and was removed (see the long comment in `vocab.py`): history
contains BOTH correct coined terms and mis-transcriptions, and nothing can tell them apart. Raw
mining suggested mis-spellings ("Superbase"); an AI "fix" pass corrupted correct coined names it
didn't know ("Filect" → "Filecat"). Correct spellings only come from (a) the niche prompt (model
knowledge) or (b) the user's own typed/edited terms. Don't reintroduce it.
