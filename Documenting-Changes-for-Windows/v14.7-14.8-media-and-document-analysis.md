# Porting v14.7.0 + v14.8.0 to Windows — media & document analysis

Two Mac releases to replicate: **v14.7.0** (video + audio analysis, single-file picker, threaded
single-file indexing) and **v14.8.0** (Word/PowerPoint/RTF/email/ebook/OpenDocument analysis,
cleaner tags, instant "View Analyzed Files"). Everything makes new file types searchable + fixes
the view's lag.

## The one architectural idea
Nothing here is a new analysis engine. Every file type fills the **same metadata fields** an image
already produces (`label`, `tags`, `caption`, `category`, `ocr_text`, `ai_source`), so search and
organize work on it with zero downstream changes. Two input patterns feed those fields:

- **Pattern A — extract text → `analyze_text()`** (documents). The indexer's non-image branch
  already does `extract_file_text() -> analyze_text() -> tags`. Adding a format = adding a text
  extractor + registering the extension. No new AI code.
- **Pattern B — media → frames/transcript** (video, audio). Sample keyframes + transcribe audio,
  feed the EXISTING vision + transcription calls, merge into the same fields.

Where it all plugs in: `_process_single_file()` in `app/core/search.py` (the per-file router) and
`extract_file_text()` in `app/core/text_extract.py` (the text dispatcher).

## 1. DOCUMENTS — Word / PowerPoint / RTF / email / ebook / OpenDocument  (v14.8.0)
**100% pure Python — port verbatim, no Windows-specific work.**

In `app/core/text_extract.py` add these extractors and wire them into `extract_file_text()`'s
dispatch + `get_supported_text_formats()`:

| type | library | how |
|------|---------|-----|
| `.docx` | `python-docx` | `docx.Document(path)` → join `.paragraphs` text + table cell text |
| `.pptx` | `python-pptx` | each slide → shapes with `has_text_frame` → `.text`, plus `slide.notes_slide` notes |
| `.rtf` | `striprtf` | `rtf_to_text(open(path).read())` |
| `.eml` | **stdlib `email`** | `BytesParser(policy=policy.default).parse(f)` → From/To/Subject/Date + body (strip HTML tags with a regex if only HTML) |
| `.epub` | `ebooklib` + `beautifulsoup4` | read `ITEM_DOCUMENT` items → `BeautifulSoup(content).get_text()`, concat chapters (cap length) |
| `.odt/.ods/.odp` | `odfpy` | `load(path)` → iterate `H` + `P` elements → `teletype.extractText(el)` |

Each extractor is wrapped in try/except returning `None` on failure (never crash indexing), and caps
output (~20k chars). Then:
- In `search.py`, add these extensions to the `ocr_text`-storage set in the non-image branch (the
  `if ext == '.csv' or ext in {...}` line) so the extracted text is stored as searchable `ocr_text`.
- `requirements.txt`: `python-docx`, `python-pptx`, `striprtf`, `ebooklib`, `beautifulsoup4`,
  `odfpy`. (`lxml` comes transitively.)
- PyInstaller spec hiddenimports: `docx`, `pptx`, `lxml`, `striprtf`, `ebooklib`, `bs4`,
  `soupsieve`, `odf` (+ `odf.opendocument/.text/.teletype`), and `collect_data_files('pptx')` +
  `collect_data_files('docx')`.

**Deferred on Mac too — `.msg` (Outlook):** `extract-msg` drags in a heavy tree (oletools + a
tkinter dep). Skip it, or write a light parser with `olefile`.

## 2. CLEAN TAGGING PROMPT  (v14.8.0) — pure Python, port verbatim
The document/text analyzer (`_gpt_text_analysis` in `app/core/vision.py`) was reusing the IMAGE
prompt, so it leaked junk tags (`document page`, the file extension, the filename, `layout: single
column`, `thumbnail`, generic `office/professional`). Replaced it with a **search-focused** prompt:
"tag a document for a file-search index — only the words a person would TYPE to find it: topics,
names, people, companies, products, tools, places, plus a short document type; NEVER the format,
filename, layout/visual descriptions, or vague filler." JSON `{type, caption, tags}`, tag cap
lowered 25 → 14. This also sharpened PDF and plain-text tags (same shared path). Port the prompt
text exactly.

## 3. AUDIO FILE ANALYSIS  (v14.7.0)
Standalone audio files (`.mp3/.wav/.m4a/.aac/.flac/.ogg/.opus/.aiff/...`). `analyze_audio()` in
`app/core/video_analysis.py`:
1. If the file is long, trim to the first 10 min (Mac uses AVFoundation export — on Windows use
   ffmpeg: `ffmpeg -i in -t 600 -vn -acodec aac out.m4a`). Short files: send as-is.
2. `transcribe_audio(path)` — the EXISTING Grok transcription backend. **Platform-independent.**
3. Tag the transcript with a dedicated prompt (`_tag_transcript()`): "label an audio clip from its
   transcript — real topics/people/tools + a category (podcast/meeting/voice memo/lecture); never
   the format or filename." Store the transcript as `ocr_text`, `ai_source="audio:transcript"`.

Add an audio branch in `_process_single_file()` (cloud-provider only). The only Windows-specific
piece is the optional trim (ffmpeg instead of AVFoundation).

## 4. VIDEO ANALYSIS  (v14.7.0) — the main platform-specific port
`analyze_video()` in `app/core/video_analysis.py`:
1. **Extract ~4 keyframes** at 12.5% / 37.5% / 62.5% / 87.5% of the duration (centers of the four
   quarters — avoids black title/end frames).
2. **One vision call with all 4 frames** (gpt-4o-mini-class vision accepts multiple images per
   message) → caption + tags. Downscale each frame to 1024px first.
3. **Extract the audio track** → `transcribe_audio()` → transcript (10-min cap). Silent videos
   (no audio track) degrade to frames-only.
4. Merge: visual caption + transcript context → tags/`caption`/`type`; transcript → `ocr_text`;
   `ai_source="video:frames+transcript"` (or `video:frames`); store `duration`.

Add a video branch in `_process_single_file()` for `.mp4/.mov/.m4v/.avi/.mkv/.webm/...`.

**Windows adaptation — replace only the two native extractors:**
- Mac: `extract_keyframes` uses AVFoundation `AVAssetImageGenerator`; `extract_audio` uses
  `AVAssetExportSession`.
- **Windows: use ffmpeg** (recommended via `imageio-ffmpeg`, which bundles the ffmpeg binary so
  there's nothing to install and it survives PyInstaller):
  - Frames: for each timestamp `t`, `ffmpeg -ss {t} -i video -frames:v 1 -q:v 2 frame.png` →
    read bytes. (Or `cv2.VideoCapture` + `set(CAP_PROP_POS_MSEC)` if you prefer opencv-python.)
  - Audio: `ffmpeg -i video -t 600 -vn -acodec aac out.m4a`.
- `analyze_video()`, `_analyze_frames()` (the multi-frame vision call), the merge logic, and the
  duration helper are **shared — port verbatim**; only `extract_keyframes`/`extract_audio` differ.

> Caveat worth knowing (same on both platforms): the `extract_audio` loop must NOT spin a UI/run
> loop. Use the async export + a simple `time.sleep` status poll (or ffmpeg's blocking subprocess).

## 5. SINGLE-FILE PICKER  (v14.7.0)
The Organize drop-zone's "click to browse" was folder-only. Drag-and-drop already handled files
(`_handle_dropped_paths` splits files vs folders and routes single files to `index_single_file`);
only the click picker was restricted.
- Mac: a native `NSOpenPanel` with `canChooseFiles=True` + `canChooseDirectories=True` +
  multi-select (one panel picks files OR folders), with a QFileDialog fallback.
- **Windows:** Qt's `QFileDialog` also can't select both files and folders in one dialog. Two clean
  options: (a) a tiny popup menu "Choose Files… / Choose Folder…" → the respective `QFileDialog`;
  or (b) the native Windows `IFileOpenDialog` with `FOS_ALLOWMULTISELECT`. Route the result into the
  existing `_handle_dropped_paths`.

## 6. THREADED SINGLE-FILE INDEXING  (v14.7.0) — pure Qt, port verbatim
`_index_individual_files` used to loop `index_single_file` on the UI thread — fine for images,
but video/audio analysis is heavy and froze the app. Now it runs on the same `IndexWorker` QThread
the folder path uses, emitting progress signals. (Audit every indexing entry point — folder,
single-file, multi-folder, re-index, auto-watcher — all must run on a worker; on Mac they do.)

---

## 7. INSTANT "VIEW ANALYZED FILES"  (v14.8.0) — pure Qt, port verbatim
The analyzed-files table (`QTableWidget`, 16 columns) rebuilt every row up front → ~735ms for
~1,150 files and growing linearly. Fixes:
- **Row cap + full-set search (the main fix):** keep the full result in `self._all_debug_rows`,
  render only the first **300** rows (`_render_debug_table(rows)`), and make the search box filter
  the **cached full set** and re-render matches (so the cap never hides a file). Split
  `refresh_debug_view` into load → `_render_filtered_debug` (filter+cap+labels) → `_render_debug_table`.
  Result: ~735ms → ~89ms, and instant at any file count.
- Hoist the per-row action-button CSS to ONE table-level stylesheet (was re-parsing CSS ~2 ×
  every row), wrap the fill in `setUpdatesEnabled(False/True)`, and drop `ResizeToContents` (it
  measured every row per column) in favor of fixed Interactive widths.

## Dependencies summary (add to Windows requirements)
- **Pure Python, identical on Windows:** `python-docx`, `python-pptx`, `striprtf`, `ebooklib`,
  `beautifulsoup4`, `odfpy` (+ transitive `lxml`). `.eml` uses stdlib only.
- **Windows media stack (replaces AVFoundation):** `imageio-ffmpeg` (bundled ffmpeg) for video
  frames + audio extraction/trim; optional `opencv-python` if you prefer cv2 for frames.
- Audio *transcription* and all tagging/vision calls are the existing cloud backend — no new deps.

## Testing (match the "real tests" bar)
For each type: generate a fixture with known content (docx/pptx/eml can be authored with the same
libs; make an rtf/odt; use a real mp4/mp3), then run `search_service._process_single_file(...)` and
assert: non-empty content tags, correct `ai_source`, transcript stored where expected, no
exception. Confirm indexing runs on the worker thread (UI stays responsive). Confirm video silent-
edge-case → frames-only, and that re-indexing a file updates its row (no duplicates). Verify the
files view opens fast and search finds a file beyond the 300-row cap.
